# 千寻（Qianxun）浏览器标签与资料工作台 PRD

- 文档版本：v0.2
- 产品阶段：MVP 待评审
- 目标平台：Chrome / Chromium 浏览器扩展（Manifest V3）
- 主要入口：覆盖浏览器新标签页
- 技术基线：现有 WXT + React + TypeScript 项目；IndexedDB + Dexie 数据层

## 1. 产品定义

千寻是一款本地优先的浏览器新标签页扩展，帮助用户把当前打开的标签页整理成可长期复用的资料集合，并在同一个工作台内完成搜索、拖拽归档、书签编辑和文本记录。

首版借鉴 Toby 的三栏工作台布局和“把标签拖进集合”的核心交互，但不复刻其品牌、视觉资产或付费协作能力。

一句话价值主张：**打开一个新标签页，就能整理当前标签、查找已存资料并记下一段内容。**

## 2. 背景与问题

目标用户在调研、项目执行和日常浏览中会持续积累标签页，常见问题包括：

- 标签页数量快速增长，窗口拥挤，稍后很难找回。
- 浏览器原生书签以树状目录为主，不适合视觉化浏览和快速重排。
- 链接与临时说明分散在书签、备忘录和文档中，缺少上下文。
- 保存、分类、改名需要多步操作，整理成本高于“先放着不管”。

## 3. 产品目标

### 3.1 MVP 目标

- 用户可以把当前窗口的标签页拖入任意集合，保存为书签卡片。
- 用户可以通过拖拽调整集合、书签和文本卡片的位置。
- 用户可以搜索已存书签、文本记事、集合及当前打开的标签页。
- 用户可以新增、编辑、移动和删除书签。
- 用户可以在集合中新增、编辑和删除纯文本记事卡片。
- 全部业务数据和界面状态无需账号即可持久保存在本地 IndexedDB，并支持完整 JSON 备份与恢复。

### 3.2 成功指标

在内部试用或小范围测试阶段，以行为完成度而非增长指标为主：

- 首次使用者能在 60 秒内创建集合并保存第一个标签页。
- 核心任务“打开新标签页 → 找到目标集合 → 保存标签”可在 3 次操作内完成。
- 在 1,000 个本地条目规模下，输入搜索词后 150ms 内更新结果。
- 拖拽保存、重排和跨集合移动的成功率达到 99%，刷新后顺序不丢失。
- 记事内容在停止输入 500ms 后自动保存，异常关闭后最多丢失最后 500ms 的输入。

## 4. 用户与核心场景

### 4.1 目标用户

- 同时处理多个项目的研发、产品、设计和运营人员。
- 经常进行资料调研、竞品收集或任务上下文切换的重度浏览器用户。
- 希望以卡片和工作区组织信息，而非维护复杂书签目录的用户。

### 4.2 核心场景

1. **快速归档**：用户打开多个参考页面，把右侧标签卡拖入“竞品调研”集合。
2. **快速找回**：用户按 `Cmd/Ctrl + K`，输入标题、网址或笔记关键词并打开结果。
3. **整理资料**：用户在集合内重排书签，或将书签拖到另一个集合。
4. **补充上下文**：用户在链接旁新增一张文本卡，记录账号说明、结论或待办。
5. **修正信息**：用户编辑书签名称、URL 或备注，避免依赖网页原始标题。

## 5. 产品结构

### 5.1 信息层级

- 工作区（Space）
  - 集合（Collection）
    - 书签卡片（Bookmark）
    - 文本记事卡片（Note）
- 当前浏览器窗口
  - 打开的标签页（Open Tab，仅实时展示，不持久化为内容）

MVP 默认创建一个“我的空间”和一个“收件箱”集合。工作区用于区分大的场景，例如工作、学习和个人；集合用于承载具体主题。

### 5.2 主界面

```text
┌──────────────┬─────────────────────────────────────┬──────────────┐
│ 工作区导航    │ 当前工作区 / 集合画布                 │ 当前窗口标签  │
│ 全局搜索      │ [集合 A] 书签卡 / 文本卡              │ 标签卡        │
│ 我的空间      │ [集合 B] 书签卡 / 文本卡              │ 标签卡        │
│ 设置          │                                     │ 标签卡        │
└──────────────┴─────────────────────────────────────┴──────────────┘
```

- 左栏：产品名、全局搜索、工作区列表、设置入口，可折叠。
- 中栏：当前工作区标题、添加集合按钮、集合列表及内容卡片，是主要操作区。
- 右栏：当前窗口的实时标签页，可折叠；点击切换标签，拖入中栏即可保存。
- 搜索态：以居中命令面板覆盖主界面，支持键盘选择和分类筛选。

### 6.7 数据、设置与恢复

| 编号 | 需求 | 优先级 | 验收标准 |
|---|---|---:|---|
| DATA-01 | IndexedDB 本地持久化 | P0 | 工作区、集合、书签、记事、排序、设置和界面状态全部写入扩展自身的 IndexedDB；不使用 `localStorage` 或 `chrome.storage` 保存业务数据 |
| DATA-02 | Dexie 数据层 | P0 | 通过 Dexie 统一定义表、索引、事务和版本迁移；业务组件不得直接操作原生 IndexedDB |
| DATA-03 | 导出完整 JSON | P0 | 用户可下载一个 UTF-8 `.json` 文件；文件包含全部表数据、数据库版本、应用版本、导出时间和记录数量，可用于完整恢复 |
| DATA-04 | 导入 JSON | P0 | 导入前校验文件类型、格式版本、表结构和必填字段；提供“合并/覆盖”选择；覆盖需二次确认 |
| DATA-05 | 原子导入与失败回滚 | P0 | 导入在单次数据库事务中完成；任一步失败时回滚全部变更，现有数据保持不变并展示错误原因 |
| DATA-06 | 数据迁移 | P0 | 数据库使用递增版本号和 Dexie migration；升级扩展时自动迁移，迁移失败不得清空旧数据 |
| DATA-07 | 清空数据 | P0 | 设置页提供清空 IndexedDB 入口，明确不可撤销并要求二次确认 |
| DATA-08 | 多设备同步 | P2 | MVP 不提供账号和云同步，IndexedDB 数据不离开本机 |

JSON 备份以“可恢复性”为准：不能只导出用户可见字段，也必须包含稳定 ID、实体关系、排序、折叠状态和设置。MVP 采用 Dexie 官方 `dexie-export-import` 扩展完成数据库与 JSON Blob 的完整导入导出；产品层额外维护应用版本、导出时间和记录统计，用于导入前校验和用户确认。

## 7. 关键交互规则

### 7.1 标签保存流程

1. 用户从右栏拖起一个标签卡。
2. 中栏可接收的集合高亮，当前目标集合显示投放占位。
3. 用户松手：系统规范化 URL，并检查目标集合是否已有相同链接。
4. 无重复则在指定位置创建书签；有重复则不创建并高亮原卡片。
5. 右下角显示短暂反馈；原浏览器标签保持打开。

### 7.2 编辑规则

- 书签通过卡片菜单进入编辑弹窗，防止误触直接修改。
- 记事卡支持就地编辑，点击卡片正文即可进入编辑态。
- 弹窗内 `Cmd/Ctrl + Enter` 保存，`Esc` 取消；有未保存修改时关闭需提示。
- 任何删除均先进入 5 秒可撤销状态；删除集合和工作区仍需显式确认。

### 7.3 URL 规范化与重复判断

- 主机名转为小写，移除默认端口和末尾无意义 `/`。
- 默认忽略 `utm_*`、`fbclid`、`gclid` 等常见追踪参数。
- 保留可能影响页面内容的普通查询参数和 hash。
- 仅在同一集合内阻止重复；不同集合可保存同一 URL，以支持不同上下文。

## 8. 视觉与体验原则

- 延续参考图的高信息密度三栏结构，但采用独立品牌、色彩和图标体系。
- 中性浅色背景，集合之间有清晰分隔；主操作色只用于投放、选中和主要按钮。
- 书签卡与文本卡通过图标、底色和排版明显区分，不能只依赖颜色。
- 默认卡片紧凑，悬停后再显示编辑、移动和删除操作，减少画面噪声。
- 支持 1280px 以上完整三栏；较窄窗口优先折叠左栏和右栏。新标签页最低支持宽度 900px。
- 交互元素最小点击区域 40×40px；提供清晰焦点样式和键盘操作路径。

## 9. 状态与异常处理

- 首次使用：展示 3 步轻量引导——创建集合、拖入标签、添加记事。
- 无工作区/集合：提供直接创建按钮，不展示空白页面。
- 无打开标签权限：说明用途并引导授权，已存内容仍可正常浏览和编辑。
- 存储失败：保留当前编辑内容，显示重试入口，禁止静默丢失。
- URL 无效：在输入框附近说明问题，不关闭编辑弹窗。
- 页面 favicon 获取失败：使用域名首字母或统一链接图标。
- 导入文件损坏或版本不兼容：不修改现有数据，并给出可理解的错误原因。

## 10. 权限与隐私

MVP 坚持最小权限：

- `tabs`：读取和切换当前窗口标签页。
- 新标签页覆盖配置：将主工作台设为新标签页。
- favicon 使用浏览器提供的本地 favicon 能力或页面标签已有信息，不主动抓取网页正文。

全部产品数据写入扩展自身源（origin）下的 IndexedDB，不申请 `storage` 权限，也不把业务数据分散到 `localStorage` 或 `chrome.storage`。不申请 `history`、`bookmarks`、网页内容读取或远程服务器权限。搜索只针对插件自身数据和当前打开标签；文本记事与 JSON 备份均不上传。首次启动和设置页需清晰展示这一边界。

## 11. 数据模型（产品级）

| 实体 | 核心字段 |
|---|---|
| Workspace | `id`, `name`, `order`, `createdAt`, `updatedAt` |
| Collection | `id`, `workspaceId`, `name`, `order`, `isCollapsed`, `createdAt`, `updatedAt` |
| BookmarkItem | `id`, `collectionId`, `type=bookmark`, `title`, `url`, `normalizedUrl`, `note?`, `faviconUrl?`, `order`, timestamps |
| NoteItem | `id`, `collectionId`, `type=note`, `content`, `order`, timestamps |
| Settings | `id`, `activeWorkspaceId`, `leftPanelCollapsed`, `rightPanelCollapsed`, 其他用户偏好 |
| AppMeta | `id`, `schemaVersion`, `appVersion`, `createdAt`, `updatedAt` |

书签与记事采用统一的集合条目排序序列，以支持两类卡片混排。

### 11.1 IndexedDB 与备份约束

- 数据库建议命名为 `qianxun`，由单一 Dexie 实例负责生命周期管理。
- 建议表为 `workspaces`、`collections`、`items`、`settings`、`appMeta`；书签与记事共同存放在 `items` 表并以 `type` 区分。
- 索引只覆盖检索、关联和排序所需字段；记事长文本保留在记录中但不直接创建 IndexedDB 索引。
- 涉及多个实体的操作必须使用 Dexie 读写事务，例如删除集合及其内容、跨集合移动、覆盖式导入。
- 备份文件名采用 `qianxun-backup-YYYY-MM-DD-HHmmss.json`。
- 导出在本地生成并由浏览器下载，不经过远程接口；导入只读取用户主动选择的文件。
- 覆盖恢复前先解析并校验完整备份，确认后再进入写事务；不可先清库再校验。

## 12. 非功能需求

- 性能：1,000 个条目下首屏可交互时间不超过 1 秒（常规桌面设备、数据已在本地）。
- 稳定性：所有写操作先生成稳定 ID，再通过 Dexie 事务原子更新相关实体与排序；写入失败不得留下半完成状态。
- 兼容性：MVP 验证最新版 Chrome 和 Edge；Firefox 构建列入 P1。
- 可访问性：核心功能可通过键盘完成；拖拽必须有菜单替代方案；颜色对比满足 WCAG AA。
- 安全性：所有用户文本按纯文本渲染；禁止把 URL、标题或记事作为 HTML 注入。
- 可维护性：IndexedDB schema 使用 Dexie 版本迁移；持久化数据包含应用 schema 版本；领域数据与视图状态分表存储。

## 13. MVP 范围

### P0：首版必须完成

- 新标签页三栏工作台及栏位折叠。
- 工作区和集合 CRUD、折叠和排序。
- 当前窗口标签展示、切换和拖拽保存。
- 书签新增、编辑、移动、排序、打开、删除及撤销。
- 纯文本记事新增、编辑、自动保存、移动、排序、删除及撤销。
- 全局搜索与命令面板键盘操作。
- IndexedDB + Dexie 本地持久化、完整 JSON 备份与恢复、首次使用引导。

### P1：MVP 后增强

- 批量选择与操作。
- 一键保存当前窗口全部标签、保存后关闭标签。

- 标签/颜色筛选、卡片多种视图密度。
- 导入浏览器原生书签、Firefox 支持。

- AI 分类、摘要或语义搜索。
- 移动端应用。

## 14. MVP 验收场景

1. **初次使用**：安装扩展后打开新标签页，用户能完成引导、创建集合并看到当前窗口标签。
2. **拖拽保存**：将右栏标签拖到空集合，刷新页面后书签仍存在且位置正确。
3. **跨集合整理**：把书签和记事分别移动到另一个集合并混排，刷新后顺序保持。
4. **编辑与撤销**：编辑书签标题和 URL 后可搜索到新内容；删除后在 5 秒内可恢复。
5. **文本记事**：输入多行中文，等待自动保存后关闭并重新打开新标签页，内容完整恢复。
6. **全局搜索**：输入中文、域名或记事片段能得到分类结果；键盘可打开书签、切换标签或定位卡片。
7. **重复处理**：同一标签重复拖入同一集合不会产生第二条记录，已有条目被高亮提示。
8. **数据恢复**：导出 JSON 备份、清空 IndexedDB、再导入备份后，工作区、集合、全部卡片、顺序、折叠状态和设置完整恢复。
9. **异常保护**：导入损坏文件不会覆盖现有数据；输入无效 URL 不会创建坏书签。
10. **权限边界**：拒绝标签权限时，已存书签和记事仍可使用，右栏展示授权说明。

## 15. 版本推进与评审门槛

### 阶段 A：可交互原型

### 阶段 B：MVP 开发

- 接入浏览器标签 API、IndexedDB + Dexie 数据层、完整 CRUD、搜索和 JSON 导入导出。

### 阶段 C：试用优化

- 根据真实数据量验证性能和拖拽稳定性。
- 只在 P0 稳定后评估 P1，不在首版中临时扩入同步、协作或 AI 能力。
